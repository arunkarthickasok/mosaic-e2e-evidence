**Key gotcha (2026-07-09, Sprint 104 — B-090 RESOLVED): Ctrl+Z undo has no effect after Puck drag — root cause is `record()` 250ms debounce, NOT focus.** Puck's `monitorHotkeys(document)` listens at document level — `document.activeElement` being `BODY` is irrelevant, Ctrl+Z always reaches Puck. **Key gotcha (2026-07-09, Sprint 104): Tier B SSR loading skeleton timing — do NOT add delays to `drag()` for non-undo tests.** Carousel, Tabs, and Live Search (`requires_ssr_preview: true`) use `buildTierBResolveData` which has its own 300ms debounce before making the SSR request. **Key gotcha (2026-07-21, Wave 1.3 — CP-UNSAVED-GUARD dist build order):** Both `vite.builder.config.ts` and `vite.frontend-editor.config.ts` build to the same `dist/` directory (`emptyOutDir: false`). The second build wins on shared chunk files (e.g., `chunk-jsx-runtime.js`). ALWAYS build in order: **builder first, frontend-editor second**. If reversed, `frontend-editor.js` imports from `chunk-jsx-runtime.js` produced by the builder build, which may be tree-shaken differently and missing exports (symptom: `The requested module './chunk-jsx-runtime.js' does not provide an export named 'l'`).

**Key gotcha (2026-07-21, Wave 1.3 — Playwright + window.confirm() deadlock):** `page.waitForEvent('dialog')` + `await locator.click()` deadlocks when the click handler calls `window.confirm()`. `confirm()` blocks JS synchronously; Playwright's click waits for JS to finish; nobody can dismiss the dialog → infinite wait. Fix: use `page.once('dialog', async (d) => { captured = d; await d.dismiss(); })` BEFORE the click. The `once` handler fires synchronously in Playwright's CDP, dismisses the dialog, JS unblocks, click resolves, assertions can run after.

**Key gotcha (2026-07-21, Wave 1.3 — Playwright void page.reload() + beforeunload):** `void page.reload()` starts a Playwright-tracked navigation. If `beforeunload` fires and the dialog is dismissed (cancel the reload), the tracked `page.reload()` promise never resolves. At test teardown Playwright cancels it and reports "Test ended." Fix: use `void page.evaluate(() => { location.reload(); })` — this fires a JS-level reload that Playwright does not track as a navigation. Pair with `page.waitForEvent('dialog')` (which resolves once beforeunload CDP event fires) before the evaluate.

**Key gotcha (2026-07-21, Wave 1.3 — Puck Ctrl+Z inside mosaic_heading):** `page.keyboard.press('Control+z')` inside a Puck canvas containing `mosaic_heading` fires Tiptap's undo (inside the heading's rich-text editor), NOT Puck's undo. Puck's Ctrl+Z handler is at document level but Tiptap captures the event first. Fix: dispatch Puck's internal `remove` action via fiber-walk instead of keyboard shortcut.

**Key gotcha (2026-07-21, Wave 1.3 — Puck dispatch 'remove' is id-keyed):** `dispatch({ type: 'remove', index: 0, zone: 'root:default-zone' })` removes ALL components sharing the same `id` field, not just the one at that index. Example: S15 uses `'w14-s15-heading'` (not the shared `'w14-admin-heading'`) so remove is unambiguous.

**Key gotcha (2026-07-21, Wave 1.3 — data-puck-component is component id not type):** The `data-puck-component` attribute on rendered Puck elements contains the component's **id field** (e.g., `'w14-test-heading'`), NOT the component type (e.g., `'mosaic_heading'`).
